# Metrics and Evaluators Reference

## 1. Metric Taxonomy

The platform provides a modular evaluator engine with both deterministic rule-based evaluators and semantic evaluators:

| Evaluator Name | Metric Class | Supported Tasks | Output Range | Key Parameters |
| :--- | :--- | :--- | :--- | :--- |
| `exact_match` | `ExactMatchEvaluator` | Factual, Classification, Code | `0.0` or `1.0` | `case_sensitive`, `strip_whitespace` |
| `contains` | `ContainsEvaluator` | Instruction following, Refusals | `0.0` to `1.0` | `keywords`, `mode` (`any`/`all`) |
| `classification` | `ClassificationEvaluator` | Sentiment, Intent, Category | `0.0` or `1.0` | `allowed_classes`, `normalize` |
| `similarity` | `SimilarityEvaluator` | Summarization, Open QA | `0.0` to `1.0` | `method` (`token_overlap`, `cosine`) |
| `json_validity` | `JSONValidityEvaluator` | Structured Extraction | `0.0` or `1.0` | `required_keys`, `schema` |
| `response_length` | `ResponseLengthEvaluator` | Conciseness, Constraints | `0.0` to `1.0` | `min_tokens`, `max_tokens` |
| `llm_judge` | `LLMJudgeEvaluator` | Complex Tone, Safety, Policy | `0.0` to `1.0` | `judge_model`, `rubric` |

## 2. Metric Implementations & Mathematical Formulations

### 2.1 Classification Precision, Recall, and F1
For multiclass evaluation over a test batch:
$$ \text{Precision} = \frac{TP}{TP + FP} $$
$$ \text{Recall} = \frac{TP}{TP + FN} $$
$$ F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} $$

### 2.2 Token-Level Overlap Similarity (Jaccard / Token-F1)
$$ \text{Overlap}(A, B) = \frac{|T_A \cap T_B|}{|T_A \cup T_B|} $$

### 2.3 JSON Schema Validity
Evaluates whether candidate text parses cleanly as valid JSON and conforms to the expected key hierarchy:
- If JSON parses cleanly and contains all expected keys $\rightarrow 1.0$
- If JSON parses cleanly but misses keys $\rightarrow \frac{|K_{\text{found}}|}{|K_{\text{expected}}|}$
- If JSON parsing throws a syntax error $\rightarrow 0.0$

## 3. Metric Limitations & Failure Modes

1. **Exact Match Fragility**: High false-negative rate when the LLM rephrases valid answers (e.g. "Paris" vs "The capital of France is Paris.").
2. **Keyword Match False Positives**: An LLM mentioning a prohibited keyword in a disclaimer (e.g. "I cannot assist with *SQL injection*") could fail naive negative keyword checks without negation parsing.
3. **Judge Self-Preference Bias**: Models used as judges (e.g. GPT-4) consistently assign higher scores to responses generated by the same family of models.
4. **Length Bias in Judges**: LLM judges systematically favor verbose answers over concise answers even when conciseness is explicitly requested in the rubric.
