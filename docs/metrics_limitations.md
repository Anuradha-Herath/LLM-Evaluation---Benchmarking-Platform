# Evaluation Metrics & Trade-Off Analysis

This document details the methodological limitations, trade-offs, and failure modes of the evaluation metrics implemented in the **LLM Evaluation & Benchmarking Platform**.

---

## 1. Lexical Metrics (Exact Match & Keyword Matching)

### Implementation
- `ExactMatchMetric`
- `ContainsKeywordMetric`

### Trade-offs & Limitations
* **Brittleness & Paraphrasing Failure**: Lexical metrics perform strict character or token comparisons. If an LLM generates a semantically perfect response using different phrasing (e.g. *"SOC 2 Type 1 evaluates design at a point in time"* vs *"Type 1 assesses design on a specific date"*), Exact Match yields `0.0`.
* **Capitalization & Formatting Sensitivity**: Although normalization (lowercasing, punctuation stripping) mitigates simple differences, markdown headers, bold text, or bullet points can cause false negatives.
* **Over-reliance on Superficial Keywords**: `ContainsKeywordMetric` checks for substring presence without evaluating syntactic context. An LLM output containing *"I will NOT refund invoice #1049"* would match the keyword `refund` and receive a positive score despite being an incorrect refusal.

---

## 2. Text Similarity Metrics (SequenceMatcher & Token Overlap)

### Implementation
- `TextSimilarityMetric` (SequenceMatcher Gestalt ratio + Jaccard token set overlap)

### Trade-offs & Limitations
* **Surface Similarity vs. Truthfulness**: High lexical overlap does not guarantee correctness. Reversing a single key word (e.g. *"The server was upgraded"* vs *"The server was NOT upgraded"*) retains ~90% sequence similarity while completely inverting the factual truth.
* **Length Penalty Inconsistencies**: Concise, direct responses comparing against wordy reference answers receive low similarity scores even if entirely correct.
* **Lack of Deep Semantic Reasoning**: Token overlap algorithms do not capture latent semantic embeddings or domain knowledge.

---

## 3. LLM-as-a-Judge Evaluation

### Implementation
- `LLMJudgeMetric`

### Trade-offs & Limitations

> [!WARNING]
> **Crucial Rule**: LLM-as-a-judge must **never be treated as ground truth**. It is a heuristic evaluator subject to model biases and non-determinism.

* **Position Bias**: LLM judges often prefer the first or second option in pairwise evaluations regardless of quality.
* **Verbosity Bias**: Larger models frequently award higher scores to longer, more elaborate responses, penalizing concise and direct answers.
* **Self-Preference Bias**: Models tend to score outputs generated by their own family (e.g., GPT-4 evaluating GPT-4 outputs) higher than outputs from competing models (e.g., Claude or Llama).
* **Non-Determinism & Temperature Variance**: Even at `temperature=0.1`, judge outputs can fluctuate across evaluation runs, requiring fixed random seeds and multi-run sampling.
* **Hallucination in Reasoning**: The judge model may hallucinate criteria missing from the rubric or misinterpret complex technical inputs.

---

## 4. Reference-Answer Dependence

### Trade-offs & Limitations
* **Single Gold-Standard Fallacy**: Most open-ended generation tasks (e.g., summarization, code generation, customer support) have many valid responses. Evaluating against a single reference answer penalizes valid alternative explanations.
* **Outdated Reference Data**: Factual reference answers tied to specific dates (e.g. current tax rates, software versions) become stale over time, causing false evaluation failures.

---

## 5. Recommended Evaluation Strategy

To achieve robust evaluation, combine multiple complementary metric layers:

1. **Deterministic Rule Checks**: Run `JSONValidityMetric` and `ResponseLengthMetric` first to ensure hard structural constraints are met.
2. **Lexical Baseline**: Apply `ExactMatchMetric` and `ClassificationMetric` for deterministic tasks (e.g., classification, extraction).
3. **LLM-as-a-Judge**: Use `LLMJudgeMetric` for open-ended, subjective tasks (e.g., customer support empathy, complex reasoning), logging the judge model name and rubric version alongside every score.
